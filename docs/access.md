# Доступ к Welcome Book: инструкция для менеджера

Сайт закрыт окном входа. Чтобы открыть онбординг, нужно ввести **логин и пароль**. По ним сайт сам решает, какую
версию показать: **Office** или **Retail**. Логины и пароли ведутся в Storyblok, разработчик для этого не нужен.

## Как выдать доступ новому сотруднику

1. Откройте Storyblok → **Content** → история **Доступ (пароли)**.
2. В поле **Пароли** нажмите **Add block** и выберите **Пароль доступа**.
3. Заполните поля:

| Поле | Что писать |
|---|---|
| **Кому** | для себя: имя или команда, например «Склад Москва». На сайте не показывается |
| **Логин** | обязательно. Например `ivan.petrov`. Регистр букв не важен |
| **Какую версию открывает** | Office или Retail |
| **Пароль** | обязательно. Лучше длинный, из нескольких слов и цифр |
| **Действует до** | необязательно. Пусто — пароль без срока. Если указать дату и время, после них пароль перестанет работать. Время по UTC (Москва — на 3 часа позже) |
| **Отключить** | галочка. Закрывает доступ, не удаляя запись |

4. Нажмите **Publish**. **Без публикации изменения не работают** — черновик сайт не видит.
5. Отправьте сотруднику логин и пароль. Новый вход заработает в течение 30 секунд после публикации.

Один логин и пароль подходят для одной версии. Если человеку нужны обе версии, заведите две записи.

## Как сменить пароль

Откройте запись, измените поле **Пароль** (или **Логин**) и нажмите **Publish**. Старая пара перестаёт работать
через 30 секунд, и тот, кто вошёл по ней, выходит из сайта. Новые данные отправьте сотруднику.

Чтобы пароль менялся каждую неделю без лишних хлопот, можно держать рядом две записи: новую и старую. Старую на
несколько дней оставляют для переходного периода, потом удаляют.

## Как закрыть доступ

- **Временно или без потери записи:** поставьте галочку **Отключить** и нажмите **Publish**.
- **Насовсем:** удалите блок и нажмите **Publish**.
- **По сроку:** заполните **Действует до**, и доступ закроется сам.

Во всех случаях человек, который уже вошёл, выходит из сайта в течение 30 секунд после публикации. Остальных сотрудников
это не затрагивает.

## Что нужно знать

- Вход без логина не работает. Общего пароля для всех нет: у каждой записи свой логин.
- Сессия держится 30 дней, потом нужно войти заново. Если запись отключили, удалили или у неё истёк срок, сессия
  закрывается раньше.
- После нескольких неверных попыток подряд вход на время блокируется.
- Пароли лежат в Storyblok открытым текстом, их видят все, у кого есть доступ к пространству. Поэтому не давайте
  доступ к этой истории тем, кому не нужно управлять паролями. На сайте пароли никому не показываются.
- Редактор Storyblok открывает сайт из Visual Editor без пароля, обе версии доступны ему сразу.
- Сайт не ведёт учёт, кто и когда входил.

## Тексты на странице входа

Заголовок, пояснение, названия полей, подсказки и текст ошибки редактируются в Storyblok: история **Вход**
(`login`). После публикации новый текст появляется на сайте не сразу, иногда нужно один-два раза обновить страницу
или подождать до часа.

## Для разработчика

- Вход: `src/app/actions.ts`, окно: `src/components/login/LoginForm.tsx`, защита страниц: `src/proxy.ts`
  (закрывает `/office` и `/retail`).
- Пароли из Storyblok читает `src/lib/access/managed.ts` (история `access`, без кэша контента, в памяти держится 30 секунд).
  Запись без логина не действует. Срок читается как UTC, нечитаемый срок считается истёкшим.
- Завести блоки и пустую историю в новом пространстве: `npm run storyblok:access`. Окно входа: `npm run storyblok:login`.
- Запасной вход через окружение Vercel (работает и без Storyblok), значения вида `логин:пароль`, несколько через
  запятую или с новой строки:

| Переменная | Что это |
|---|---|
| `ACCESS_SECRET` | длинная случайная строка, подпись cookie. Без неё войти нельзя |
| `ACCESS_OFFICE` | входы для Office |
| `ACCESS_RETAIL` | входы для Retail |

  Запись без `логин:` не действует. После смены переменных нужен redeploy.
- Сессия — подписанная cookie `wb_access` на 30 дней, в ней отпечаток пары логин + пароль. Пока пара есть в списке,
  сессия живёт.
