# Доступ к Welcome Book

Сайт закрыт окном входа (`/`): почта + пароль. **Пароль определяет версию** - Office или Retail.
Без входа `/office` и `/retail` отправляют на окно входа (`src/proxy.ts`).

## Настройка (Vercel → Settings → Environment Variables)

| Переменная | Что это |
|---|---|
| `ACCESS_SECRET` | длинная случайная строка, подпись cookie. Без неё войти нельзя |
| `ACCESS_OFFICE` | пароли для Office, через запятую или с новой строки |
| `ACCESS_RETAIL` | пароли для Retail |
| `ACCESS_EMAIL_DOMAINS` | необязательно: `trendsettercrew.com` - пускает только почту этого домена |

После смены переменных нужен redeploy.

## Как раздавать и менять пароли

- **Один общий пароль на версию** (сейчас): по одному значению в `ACCESS_OFFICE` и `ACCESS_RETAIL`.
- **Новый пароль, например раз в неделю**: заменить значение в переменной и сделать redeploy. Все сессии по старому
  паролю закрываются сразу. Чтобы не выкидывать людей посреди недели, на переход можно оставить оба пароля в списке
  (`новый,старый`), а старый убрать через несколько дней.
- **Свой пароль каждому сотруднику**: в `ACCESS_OFFICE` / `ACCESS_RETAIL` по паролю на человека. Убрать пароль из списка
  - значит закрыть доступ только этому человеку, остальные не затронуты.

Сессия живёт 30 дней или до тех пор, пока пароль, по которому вошли, есть в списке.

## Что не защищено

Почта проверяется только по форме (и по домену, если он задан), а не по списку людей. Если нужен именно именной вход
(`почта + личный пароль`, отзыв доступа без redeploy), следующий шаг - хранить пользователей в базе (например Vercel KV
или Edge Config) вместо переменных окружения.

## Тексты окна входа

Редактируются в Storyblok: история **Вход** (`login`). Чего редактор не заполнил, берётся из `src/content/seed/login.ts`.
Завести блок и историю в новом пространстве: `npm run storyblok:login`.

Редактор Storyblok входит через `/api/preview` и получает доступ к обеим версиям без пароля.
